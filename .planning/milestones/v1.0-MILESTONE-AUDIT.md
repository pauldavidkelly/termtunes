### Data Flow Integrity

All data flows verified correct:

**Config data flow:**
- Loaded once at startup (main.rs:65)
- Mutated for auth token and favorites
- Read for session restore
- Never duplicated or stale

**Session data flow:**
- Built from App state on exit
- Written atomically to session.toml
- Loaded on startup
- Used to restore position and settings

**Audio data flow:**
- Downloaded by background thread
- Sent via mpsc channel
- Decoded by Player
- Optionally tapped for visualizer
- Played by rodio Sink
- Cached for Repeat One

**Visualizer data flow:**
- Created once at app startup
- Shared via Arc<Mutex<>> (thread-safe)
- Written by audio thread (try_lock, non-blocking)
- Read by UI thread for FFT
- Zero overhead when disabled
