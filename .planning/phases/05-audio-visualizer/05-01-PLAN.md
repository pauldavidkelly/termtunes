**Add dependency** to Cargo.toml:

```toml
spectrum-analyzer = "1.7"
```

**Create `src/visualizer.rs`** with these components:

1. **SampleBuffer type** -- `Arc<Mutex<Vec<f32>>>` shared between audio thread (writes) and UI thread (reads).

2. **VisualizerData struct** -- holds the `SampleBuffer`, sample rate (`u32`), and a `has_new_data: bool` flag (set by audio thread on write, cleared by UI after FFT). Wrap in `Arc<Mutex<VisualizerData>>`.

3. **VisualizerSource<S: Source<Item = f32>>** -- rodio Source wrapper that:
   - Delegates all Source trait methods (channels, sample_rate, current_span_len, total_duration) to inner source
   - Implements Iterator: calls inner.next(), copies left-channel samples to the shared buffer using `try_lock()` (skip on lock failure -- no audio impact), tracks channel position to extract mono from stereo (only write when `channel_counter % channels == 0`), uses circular write with `write_pos % fft_size`
   - FFT_SIZE constant = 2048
   - On first sample, store the sample_rate in VisualizerData

4. **NUM_BARS constant** = 16 (number of frequency bands). Will be adjusted dynamically at render time based on available width, but 16 is the default.

5. **compute_spectrum_bars(data: &Arc<Mutex<VisualizerData>>, num_bars: usize) -> Vec<f64>** function that:
   - Locks the data, checks `has_new_data` flag (return previous values / zeros if false to save CPU when paused)
   - Clones the sample buffer and sample_rate, sets `has_new_data = false`, releases lock
   - Applies `hann_window` from spectrum_analyzer::windows
   - Calls `samples_fft_to_spectrum` with the sample rate, FrequencyLimit::Range(20.0, 16000.0), and `divide_by_N_sqrt` scaling
   - Bins the resulting frequency-magnitude pairs into `num_bars` bands using logarithmic spacing (see research Code Examples: `bin_spectrum_logarithmic`)
   - Returns Vec<f64> of normalized magnitudes (0.0..1.0)

6. **VisualizerState struct** -- holds `smoothed_bars: Vec<f64>` and provides:
   - `update(&mut self, target: &[f64])` -- applies exponential smoothing: fast attack (0.7) for rising bars, slow decay (0.9) for falling bars (see research Code Examples: `smooth_bars`)
   - `bars(&self) -> &[f64]` -- returns current smoothed values

7. **render_visualizer(frame, area, bar_values: &[f64])** function that:
   - Converts f64 magnitudes (0.0..1.0) to `(&str, u64)` tuples scaled to 0..100
   - Creates a BarChart with block title " Visualizer ", Borders::ALL, DarkGray border, bar_width=1, bar_gap=0, bar_style fg=Cyan, max(100)
   - Renders the widget

8. **create_visualizer_data(fft_size: usize) -> Arc<Mutex<VisualizerData>>** -- factory function that creates the shared data with a pre-allocated buffer of `fft_size` zeros.

**Modify `src/player.rs`**:

- Add `use crate::visualizer::{VisualizerSource, VisualizerData};`
- Change `load_and_play` signature to accept an optional `visualizer_data: Option<Arc<Mutex<VisualizerData>>>`:
  ```rust
  pub fn load_and_play(&mut self, audio_bytes: Vec<u8>, track_name: String, volume: f32, visualizer_data: Option<Arc<Mutex<VisualizerData>>>) -> Result<()>
  ```
  After creating the Decoder, if `visualizer_data` is Some, wrap the decoder's source in `VisualizerSource::new(source, visualizer_data, FFT_SIZE)` before appending to the Sink. Otherwise append the source directly (same as current behavior).

- Change `replay_current` signature similarly to accept `visualizer_data: Option<Arc<Mutex<VisualizerData>>>` and wrap the decoder if provided.

**Modify `src/main.rs`**: Add `mod visualizer;` declaration.

**Important implementation notes:**
- Use `try_lock()` (not `lock()`) in the audio thread to never block playback
- The VisualizerSource wrapper must use `self.inner.channels()` to determine stereo/mono and only copy left channel samples
- FFT is NOT done on the audio thread -- only sample copying happens there
- The sample buffer is a fixed-size Vec<f32> initialized to zeros (circular buffer pattern)

4. Create `render_visualizer_area(frame: &mut Frame, app: &App, area: Rect)`:
   - Calculate dynamic num_bars from available width: `let num_bars = (area.width.saturating_sub(2)) as usize;` (subtract 2 for borders). Clamp to 4..=64.
   - Call `visualizer::render_visualizer(frame, area, app.visualizer_bars());` passing the current smoothed bar values.
   - Note: The number of bars should match between compute and render. Since compute runs before draw, and the UI sets num_bars, store the dynamic count in app via `app.set_visualizer_num_bars(num_bars)` -- but since render takes `&App` not `&mut App`, the dynamic bar count adjustment should happen in the update_visualizer call. A simpler approach: have compute_spectrum_bars always return the number of bars that VisualizerState was initialized with, and in render, interpolate/subsample to match the display width. OR: initialize VisualizerState with a reasonable max (e.g., 64 bars) and in render, use only the first `num_bars` values. Choose the simpler approach: compute a fixed 32 bars (enough for most widths), render uses `min(32, available_width - 2)` bars from the array.
