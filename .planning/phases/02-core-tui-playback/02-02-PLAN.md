Complete rewrite of ui.rs. The new layout has two modes:

**When player is active (now_playing exists):** Vertical split into main content area (Fill) + player bar (3 lines).
**When no player:** Vertical split into main content area (Fill) + single-line status bar (1 line).

Add these imports at the top:
```rust
use ratatui::layout::{Constraint, Layout, Rect, Alignment};
use ratatui::style::{Color, Modifier, Style};
use ratatui::text::{Line, Span};
use ratatui::widgets::{Block, Borders, LineGauge, List, ListItem, Paragraph};
use ratatui::Frame;

use crate::app::{App, AppView};
```

**1. Main render function:**

```rust
pub fn render(frame: &mut Frame, app: &mut App) {
    let area = frame.area();
    let has_player_bar = app.now_playing().is_some();
    let bar_height = if has_player_bar { 3 } else { 1 };

    let [main_area, bar_area] =
        Layout::vertical([Constraint::Fill(1), Constraint::Length(bar_height)])
            .areas(area);

    // Render main content based on current view
    match app.view() {
        AppView::Playlists => render_playlists(frame, app, main_area),
        AppView::Tracks | AppView::Playing => render_tracks(frame, app, main_area),
        AppView::Downloading => render_downloading(frame, main_area),
    }

    // Render player bar or status bar
    if has_player_bar {
        render_player_bar(frame, app, bar_area);
    } else {
        render_status_bar(frame, app, bar_area);
    }
}
```

**2. render_playlists** -- keep largely the same as Phase 1 but ensure it uses the AppView import.

**3. render_tracks** -- enhance to show a playing indicator next to the currently playing track. When rendering items, check if `app.now_playing()` exists and the item index matches the playing track's index. Prefix with a playing indicator (e.g., a musical note or ">>") for the currently playing track. Use `current_track_index` -- but since we don't have a direct accessor for it, use the `now_playing()` track_name to match against the track title (or add a `current_track_index()` accessor -- PREFERRED: add `pub fn current_track_index(&self) -> Option<usize>` to app.rs if not already present, reading `self.current_track_index`).

IMPORTANT: If you need to add a `current_track_index()` accessor to app.rs, do so. This is a minor addition to support the UI.

For the track list items, format as: `"  {title} - {artist}"` for normal tracks, and `">> {title} - {artist}"` for the currently playing track. Use different colors: playing track in Green+Bold, others in default.

**4. render_downloading** -- keep the same.

**5. render_player_bar** -- the core new function. Split the 3-line area vertically into three rows of 1 line each:

**Line 1 (track info):** State icon + track name + " - " + artist + " - " + album.
- State icon: " >> " (green, bold) when playing, " || " (yellow, bold) when paused, " -- " (dark gray) when stopped/finished.
- Track name: white, bold.
- Separators: dark gray.
- Artist: cyan.
- Album: yellow.

Use `Line::from(vec![Span::styled(...), ...])` for multi-colored rendering.

**Line 2 (progress bar):** Use `LineGauge` widget.
- Compute ratio: `elapsed_secs / total_secs`, clamped to 0.0..=1.0. CRITICAL: LineGauge panics if ratio > 1.0, and get_pos() can briefly exceed duration.
- filled_style: fg(Color::Cyan)
- unfilled_style: fg(Color::DarkGray)
- If total duration is 0, use ratio 0.0.

Get elapsed from `app.player().unwrap().get_pos()`. Get total from `app.now_playing().unwrap().duration_ms`.

**Line 3 (status):** Playback state + volume + elapsed/total time.
- Playback state: " Playing " (green) or " Paused " (yellow) or " Stopped " (dark gray).
- Separator: " | " (dark gray).
- Volume: "Vol: {N}%" (white). Compute as `(player.volume() * 100.0).round() as u8`.
- Separator: " | " (dark gray).
- Time: "{elapsed_mm:ss} / {total_mm:ss}" (white).

**6. format_duration helper:**
```rust
fn format_duration(d: std::time::Duration) -> String {
    let total_secs = d.as_secs();
    format!("{:02}:{:02}", total_secs / 60, total_secs % 60)
}
```

**8. Error message display:** Keep the error message priority rendering from Phase 1 -- if `app.error_message()` is Some, show red error bar instead of player bar.

The error handling should be in render() itself: if there's an error, render a 1-line error bar instead of the player bar. The existing pattern from render_status_bar should be adapted: check error_message first, then render player bar or status bar.

Actually, the simplest approach: in `render_player_bar`, if `app.error_message()` is Some, render only the error message in the first line and leave lines 2-3 as the progress/status. Or better: render error in the status bar position (line 3 of the player bar) in red, replacing the normal status line. This way the track info and progress are still visible even during transient errors.
