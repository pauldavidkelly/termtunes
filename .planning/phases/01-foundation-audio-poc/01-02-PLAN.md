    **Step 1: Create src/auth.rs -- Plex PIN-based OAuth**

    Implement the complete PIN authentication flow per research Pattern 2:

    Required headers on ALL plex.tv requests:
    - `X-Plex-Product: "TermTunes"`
    - `X-Plex-Client-Identifier: {client_id from config}`
    - `Accept: application/json`

    Functions to implement:

    - `build_plex_headers(client_id: &str) -> reqwest::header::HeaderMap` -- constructs the common headers. Reused by both auth.rs and plex.rs.

    - `create_pin(client: &reqwest::Client, client_id: &str) -> Result<PinResponse>` -- POST to `https://plex.tv/api/v2/pins` with query param `strong=true`. Returns PinResponse with `id`, `code`, `auth_token` fields.

    - `check_pin(client: &reqwest::Client, pin_id: u64, client_id: &str) -> Result<PinResponse>` -- GET to `https://plex.tv/api/v2/pins/{pin_id}`. Returns updated PinResponse (auth_token may now be Some).

    - `poll_for_auth(client: &reqwest::Client, client_id: &str) -> Result<String>` -- Creates PIN, returns the auth URL string for display, then polls check_pin every 1 second until auth_token is non-null. Timeout after 5 minutes (300 polls). Return the auth_token.

    Actually, split this so the caller can display the URL before polling:
    - `start_auth(client: &reqwest::Client, client_id: &str) -> Result<(u64, String, String)>` -- Creates PIN, returns `(pin_id, pin_code, auth_url)`. Auth URL format: `https://app.plex.tv/auth#?clientID={client_id}&code={code}&context%5Bdevice%5D%5Bproduct%5D=TermTunes`
    - `wait_for_auth(client: &reqwest::Client, pin_id: u64, client_id: &str) -> Result<String>` -- Polls check_pin every 1s until auth_token is Some. 5 minute timeout. Returns the token.

    - `validate_token(client: &reqwest::Client, token: &str, client_id: &str) -> Result<bool>` -- GET to `https://plex.tv/api/v2/user` with `X-Plex-Token: {token}` header. Returns true if 200, false if 401, errors on network failure.

    Serde structs:
    ```rust
    #[derive(Deserialize)]
    struct PinResponse {
        id: u64,
        code: String,
        #[serde(rename = "authToken")]
        auth_token: Option<String>,
    }
    ```

    **Step 2: Create src/plex.rs -- Plex API client**

    Implement the Plex server API client:

    - `PlexClient` struct: holds `client: reqwest::Client`, `server_url: String`, `token: String`, `client_id: String`.

    - `PlexClient::new(server_url: &str, token: &str, client_id: &str) -> Self`

    - `discover_servers(client: &reqwest::Client, token: &str, client_id: &str) -> Result<Vec<PlexServer>>` -- GET `https://plex.tv/api/v2/resources?includeHttps=1&includeRelay=1` with auth headers. Filter for entries where `provides` contains "server". Return list of `PlexServer { name, client_identifier (machine ID), connections: Vec<Connection> }`. Pick the best connection per server: prefer local connections, then non-relay direct connections.

    - `PlexClient::fetch_playlists(&self) -> Result<Vec<Playlist>>` -- GET `{server_url}/playlists?playlistType=audio` with `X-Plex-Token` and `Accept: application/json`. Deserialize using the serde structs from research (PlaylistContainer > MediaContainer > Metadata[]).

    - `PlexClient::fetch_tracks(&self, playlist_key: &str) -> Result<Vec<Track>>` -- GET `{server_url}/playlists/{ratingKey}/items` with auth headers. Deserialize Track with nested Media > Part.

    - `PlexClient::stream_url(&self, part_key: &str) -> String` -- Construct `{server_url}{part_key}?X-Plex-Token={token}`.

    Serde structs per research Pattern (Plex Playlist + Track Fetching):
    - `PlaylistContainer`, `PlaylistMediaContainer`, `Playlist` (ratingKey, title, leafCount, duration)
    - `TrackContainer`, `TrackMediaContainer`, `Track` (ratingKey, title, grandparentTitle as artist, parentTitle as album, duration, Media[])
    - `Media` (Part[]), `Part` (key)
    - `PlexServer` (name, clientIdentifier, connections[]), `Connection` (uri, local)
    - `ResourcesResponse` -- wrapper for the resources endpoint

    Use `#[serde(default)]` on optional fields. Use `#[serde(rename = "...")]` for camelCase Plex field names.

    IMPORTANT: Include `Accept: application/json` on EVERY request to both plex.tv AND the local server. Without this, Plex returns XML.

    **Step 2: Update src/app.rs with auth-integrated startup**

    Add a tokio async runtime for the auth and API calls. The main entry can use `#[tokio::main]` or create a runtime manually. Since the event loop is synchronous (crossterm polling), use a tokio runtime only for async HTTP operations.

    Update `App` struct to include:
    - `plex_client: Option<PlexClient>` -- set after successful auth + server selection
    - `playlists: Vec<Playlist>` -- fetched after connection
    - `tracks: Vec<Track>` -- fetched after playlist selection

    Implement `App::authenticate(&mut self) -> Result<()>`:
    1. Check if config has a `last_server` with a token
    2. If yes, validate token via `auth::validate_token()` (run async via tokio runtime)
    3. If token is valid, create PlexClient from stored server config, fetch playlists, done
    4. If token is invalid OR no last_server, temporarily exit alternate screen (so user can see URL), run PIN auth flow:
       a. Call `auth::start_auth()` to get PIN details and auth URL
       b. Display: "Open this URL in your browser:" followed by the auth URL, then "Waiting for authentication..."
       c. Call `auth::wait_for_auth()` to poll until token received
       d. Call `plex::discover_servers()` with new token
       e. If multiple servers, present a simple numbered list for selection; if one server, auto-select
       f. Save server to config: create `ServerConfig` with name, best connection URL, token. Set `last_server` to server's machine identifier
       g. Call `config::save_config()`
       h. Re-enter alternate screen, create PlexClient, fetch playlists

    Per locked decision: On expired/invalid token, automatically prompt re-authentication (no error messages, just restart PIN flow).

    **Step 3: Update event loop to show playlists and allow selection**

    After successful auth, the main area should display a list of playlist names using ratatui's `List` widget with `ListState`. This is the "simple CLI menu" per locked decisions.

    Navigation per research (CLI Menu pattern):
    - `j` or Down arrow: move selection down
    - `k` or Up arrow: move selection up
    - `Enter`: select playlist (fetches tracks, stores them -- playback comes in Plan 03)
    - `q`: quit

    After selecting a playlist, fetch its tracks and display them in the same list format. Track display: "{title} - {artist}" for each track.

    The status bar (bottom line) should show connection info: "Connected to {server_name} | {playlist_count} playlists" or after playlist selection: "{playlist_name} | {track_count} tracks".

    App state machine (simple enum):
    - `AppState::Playlists` -- showing playlist list
    - `AppState::Tracks` -- showing tracks in selected playlist

    Press `Escape` or `Backspace` in Tracks state to go back to Playlists.

    **IMPORTANT:** The auth flow should happen BEFORE entering the TUI event loop. Temporarily leave alternate screen for auth URL display (use `crossterm::execute!(stdout(), LeaveAlternateScreen)` then re-enter with `EnterAlternateScreen` after auth completes). This keeps auth output readable.
