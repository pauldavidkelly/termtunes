    **Step 1: Create src/player.rs -- Audio engine**

    Implement per research Pattern 3 (Audio Download and Playback via Rodio):

    ```rust
    pub struct Player {
        _stream: OutputStream,    // MUST live as long as Sink -- dropping kills audio
        sink: Sink,
        audio_data: Option<Vec<u8>>,  // Keep for WSL2 stream recreation workaround
        current_track: Option<String>, // Track name for status display
    }
    ```

    Methods:
    - `Player::new() -> Result<Self>` -- Create OutputStream::try_default() and Sink::connect_new(&stream.mixer()). Per research: OutputStream MUST be stored, not dropped.

    - `Player::download_track(url: &str) -> Result<Vec<u8>>` -- Use `reqwest::blocking::get(url)?.bytes()?.to_vec()`. This is a static method (no &self) since it doesn't need the player state. Run this on a background thread via `std::thread::spawn` or `tokio::task::spawn_blocking` to avoid blocking the UI thread.

    - `Player::load_and_play(&mut self, audio_bytes: Vec<u8>, track_name: String) -> Result<()>` -- Stop current playback (`self.sink.stop()`), store audio_data, create `Cursor::new(audio_bytes)`, decode with `Decoder::new(cursor)?`, append to sink. Store track_name for status display.

    - `Player::toggle_pause(&self)` -- If `sink.is_paused()` call `sink.play()`, else `sink.pause()`. Per locked decision: spacebar toggles, play/pause ONLY in Phase 1.

    - `Player::is_paused(&self) -> bool` -- Returns `sink.is_paused()`.

    - `Player::is_playing(&self) -> bool` -- Returns `!sink.is_paused() && !sink.empty()`.

    - `Player::is_finished(&self) -> bool` -- Returns `sink.empty()`.

    - `Player::current_track_name(&self) -> Option<&str>` -- Returns current_track as ref.

    **Step 2: Create src/ui.rs -- TUI rendering**

    Extract rendering from app.rs into a dedicated module. Implement per research (Status Bar UI + CLI Menu patterns):

    - `pub fn render(frame: &mut Frame, app: &App)` -- Main render function that delegates to sub-renderers based on app state.

    Layout: Vertical split -- main area (Fill) + status bar (Length 1).

    Main area rendering by state:
    - `AppState::Playlists` -- ratatui `List` widget with playlist titles, highlighted selection, Block with title "Playlists"
    - `AppState::Tracks` -- ratatui `List` widget with "{title} - {artist}" format, highlighted selection, Block with title showing playlist name
    - `AppState::Downloading` -- centered "Downloading track..." message (shown while track is being fetched)

    Status bar (bottom line, always visible):
    - When no track playing: " TermTunes | q:quit j/k:navigate Enter:select"
    - When track playing: " >> {track_name} " with green background
    - When track paused: " || {track_name} " with yellow background
    - Use `Paragraph` widget with `Style::default().fg(Color::White).bg(Color::DarkGray)` for default, colored variants for play/pause states.

    **Step 3: Update src/app.rs -- Wire playback into event loop**

    Add to App struct:
    - `player: Option<Player>` -- initialized lazily when first track is played
    - `app_state: AppState` enum (Playlists, Tracks, Downloading, Playing)
    - `status_message: String` -- for status bar

    Update the event loop:

    1. On `Enter` key in `AppState::Tracks` state:
       a. Get the selected track's Part key from `self.tracks`
       b. Construct stream URL via `self.plex_client.stream_url(part_key)`
       c. Set state to `AppState::Downloading`
       d. Download track bytes on a background thread (spawn std::thread, send bytes back via std::sync::mpsc channel)
       e. Once bytes received, initialize Player if needed, call `player.load_and_play(bytes, track_name)`
       f. Set state to `AppState::Playing` (or back to Tracks with playback active)

    2. On `Space` key (any state with active player):
       a. Call `player.toggle_pause()`

    3. The render function should be called via `terminal.draw(|frame| ui::render(frame, &app))`

    4. Check for download completion on each loop iteration (try_recv on mpsc channel).

    5. Handle audio download in a non-blocking way: the event loop continues rendering while download happens in the background. Status bar shows "Downloading..." during this time.

    Update module declarations in main.rs: add `mod player; mod ui;`

    **CRITICAL per research:** Set `PULSE_LATENCY_MSEC=60` environment variable at startup (in main.rs) to improve WSL2 audio latency: `std::env::set_var("PULSE_LATENCY_MSEC", "60");` -- do this BEFORE creating the Player/OutputStream.

    **Step 4: Ensure track selection triggers download + playback**

    The full flow: Playlists -> select -> Tracks -> select -> Download -> Play -> Spacebar to pause/resume -> q to quit.

    After track starts playing, user stays on the Tracks view and can select another track (which stops current and starts new). This keeps the UI simple for Phase 1.

  <name>Task 2: Create automated terminal restoration test script</name>
  <files>

  <action>
    Create `scripts/test_terminal_restore.sh` per locked decision: "Automated validation script that launches app, kills it various ways, checks terminal state."

    The script tests four exit paths: quit (q), Ctrl+C (SIGINT), kill (SIGTERM), and SIGHUP.

    Script logic for each test case:
    1. Record terminal state before test (`stty -g` saves settings)
    2. Launch the app in the background
    3. Wait briefly for TUI to initialize (1-2 seconds)
    4. Trigger the exit method:
       - **q key test:** Send 'q' keypress via `echo q | ...` or use `/proc/$PID/fd/0`, OR skip this one since it requires terminal interaction. Instead, test the other three signal-based exits since those are automatable.
       - **SIGINT test:** `kill -SIGINT $PID`
       - **SIGTERM test:** `kill -SIGTERM $PID`
       - **SIGHUP test:** `kill -SIGHUP $PID`
    5. Wait for process to exit (up to 5 seconds)
    6. Check terminal state:
       - `stty -g` matches saved settings (raw mode disabled, echo restored)
       - Cursor is visible (check with `tput cnorm` comparison or just verify terminal is responsive)
       - Not in alternate screen (check that normal scrollback is visible)
    7. Report PASS or FAIL for each test

    Output format:
    ```
    Testing terminal restoration...
    [PASS] SIGINT (Ctrl+C): Terminal restored cleanly
    [PASS] SIGTERM (kill): Terminal restored cleanly
    [PASS] SIGHUP: Terminal restored cleanly

    Results: 3/3 passed
    ```

    Make the script executable. The script should:
    - Build the binary first: `cargo build --release 2>/dev/null || cargo build`
    - Use the built binary path
    - Clean up any leftover processes on exit (trap EXIT)
    - Skip tests if binary doesn't compile

    NOTE: The script tests signal handling, not the q-key exit (which requires interactive terminal input). The q-key exit is verified manually in the checkpoint task.
  </action>
  <verify>
    1. `bash scripts/test_terminal_restore.sh` runs successfully
    2. All three signal tests pass (SIGINT, SIGTERM, SIGHUP)
    3. Terminal state is clean after script completes
    4. Script properly cleans up background processes
  </verify>
  <done>
    Automated script validates terminal restoration after SIGINT, SIGTERM, and SIGHUP. All three tests pass, confirming the terminal lifecycle management from Plan 01 works correctly under signal termination.
