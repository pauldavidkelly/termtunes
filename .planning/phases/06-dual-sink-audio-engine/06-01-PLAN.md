**Step 3: Add ambient methods**

`load_ambient(&mut self, audio_bytes: Vec<u8>, track_name: String, volume: f32) -> Result<()>`:
- Stop old ambient sink if any (`if let Some(ref sink) = self.ambient_sink { sink.stop(); }`)
- Create fresh sink: `Sink::connect_new(self._stream.mixer())`
- Set volume: `new_sink.set_volume(volume.clamp(0.0, 1.0))`
- Decode audio bytes using `Decoder::builder().with_data(Cursor::new(audio_bytes.clone())).build()?`
- Note: ambient does NOT need `with_byte_len` or `with_seekable` (no seeking on ambient tracks)
- Note: ambient does NOT wrap with VisualizerSource (visualizer taps main channel only)
- Append source to new sink
- Store: `self.ambient_sink = Some(new_sink)`, `self.ambient_audio_data = Some(audio_bytes)`, `self.ambient_track_name = Some(track_name)`
- Log: `tracing::info!(channel = "ambient", track = %track_name, "Ambient track loaded")`

`stop_ambient(&mut self)`:
- If ambient_sink is Some, call `.stop()` on it
- Set ambient_sink = None, ambient_audio_data = None, ambient_track_name = None
- Log: `tracing::info!(channel = "ambient", "Ambient stopped")`

`is_ambient_finished(&self) -> bool`:
- Return `self.ambient_sink.as_ref().map_or(false, |s| s.empty())`
- Note: returns false when no ambient is loaded (no ambient = not "finished")

`has_ambient_data(&self) -> bool`:
- Return `self.ambient_audio_data.is_some()`

`replay_ambient(&mut self, volume: f32) -> Result<()>`:
- Clone ambient_audio_data (return error if None)
- Stop old ambient sink, create fresh sink on `self._stream.mixer()`
- Set volume, decode from cached bytes, append to new sink
- Update self.ambient_sink = Some(new_sink)
- Log: `tracing::info!(channel = "ambient", "Ambient track loop restarted")`

`set_ambient_volume(&self, vol: f32)`:
- If ambient_sink is Some, call `.set_volume(vol.clamp(0.0, 1.0))`

`ambient_track_name(&self) -> Option<&str>`:
- Return `self.ambient_track_name.as_deref()`

`set_main_volume(&self, vol: f32)`:
- `self.main_sink.set_volume(vol.clamp(0.0, 1.0))`
- (Replaces the existing set_volume -- rename for clarity now that there are two channels)

**Important: Do NOT modify `load_and_play()`** beyond the sink rename. It must ONLY operate on `self.main_sink`. The ambient sink is never touched by main playback methods. Same for `replay_current()` -- only touches `self.main_sink`.

Per user decision (CONTEXT.md): Use regular `Sink` (not `SpatialSink`). Research confirmed SpatialSink is for 3D positional audio and is the wrong type. The user's intent (two independent sinks on shared mixer) is correct.

**Step 3: Implement volume budget enforcement**

Add method `apply_volume_budget(&mut self)`:
```rust
/// Enforce volume budget: main + ambient <= 1.0, then scale by master.
///
/// Per user decision: when volumes exceed budget, auto-scale both
/// proportionally to fit. Master volume applies AFTER budget enforcement.
fn apply_volume_budget(&mut self) {
    let sum = self.saved_volume + self.ambient_volume;
    let (main_budgeted, ambient_budgeted) = if sum > 1.0 {
        let scale = 1.0 / sum;
        (self.saved_volume * scale, self.ambient_volume * scale)
    } else {
        (self.saved_volume, self.ambient_volume)
    };

    // Apply master volume after budget enforcement
    let main_final = main_budgeted * self.master_volume;
    let ambient_final = ambient_budgeted * self.master_volume;

    if let Some(player) = &self.player {
        player.set_main_volume(main_final);
        player.set_ambient_volume(ambient_final);
    }
}
```

**Step 4: Wire budget into existing volume controls**

Modify `volume_up()`:
- Instead of calling `player.volume_up()` directly:
  ```rust
  fn volume_up(&mut self) {
      self.saved_volume = (self.saved_volume + 0.05).min(1.0);
      self.apply_volume_budget();
  }
  ```

Modify `volume_down()`:
- Instead of calling `player.volume_down()` directly:
  ```rust
  fn volume_down(&mut self) {
      self.saved_volume = (self.saved_volume - 0.05).max(0.0);
      self.apply_volume_budget();
  }
  ```

Note: This changes volume management from "Player owns volume state" to "App owns volume state, Player receives computed values." The `saved_volume` field already existed on App for persistence. Now it becomes the authoritative source. Remove the `player.volume()` read-back from volume_up/volume_down since App now tracks the value directly.

**Step 5: Wire budget into playback start**

In `check_download_complete()`, after `player.load_and_play(...)` succeeds, call `self.apply_volume_budget()` to ensure the new main_sink gets the budget-enforced volume (instead of relying on `self.saved_volume` passed to `load_and_play`). The `load_and_play` call still receives `self.saved_volume` for the initial Sink volume, but `apply_volume_budget()` immediately corrects it if ambient is active.

Similarly in `advance_track()` after `player.replay_current()`, call `self.apply_volume_budget()`.

**Step 6: Add ambient mute/unmute helpers** (for use by Plan 06-02)

```rust
/// Mute ambient channel by setting its volume to 0.

    self.ambient_volume = 0.7;

```

Note: The unmute restoring 0.7 is a simplification. A more sophisticated approach would save the pre-mute volume, but the user decision says "Set volume to 0 (simple, no separate mute state needed)" which implies simplicity is preferred. Phase 8 (UI controls) can refine this if needed.
